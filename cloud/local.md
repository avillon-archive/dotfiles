# 클라우드 환경 조항

Claude Code 클라우드 세션(Anthropic 관리 VM)에서만 성립하는 조항이다. 공통 원칙은 `~/.claude/CLAUDE.md` 가 갖는다. 클라우드 환경의 setup script 가 이 레포를 `/root/dotfiles` 에 clone 하고 이 파일을 `~/.claude/rules/local.md` 로 연결한다.

## 환경

- Ubuntu 24.04 x86_64 VM 이고 `HOME` 은 `/root` 다. Python 실행 명령은 `python3`.
- **지침 파일은 읽기 전용 사본이다.** `/root/dotfiles` 는 세션 시작 시점의 clone 이므로 지침 수정은 클라우드 세션에서 하지 않는다. 고칠 점을 발견하면 보고에 적는다.
- **`~/.claude/memory/` 는 이 환경에 없다.** 지침의 `→ 상세`·`→ 근거` 포인터는 끊겨 있으니 포인터를 따라가려 하지 말고 지침 본문 조항만 따른다.
- 서브에이전트 중첩 깊이 상한은 클라우드 환경 변수 `CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH=2` 로 정한다 — 메인 루프 → 서브에이전트 → Haiku 까지만 허용한다(전역 §Haiku 보조 위임).
- 각 클라우드 세션은 VM 을 독점하므로 로컬 실행 자원(포트·브라우저·워킹 트리)은 다른 세션과 겹치지 않는다. 겹치는 것은 원격 브랜치이고, 특히 main 이다(§Git).
- 몇 분 동안 활동이 없으면 VM 은 파일을 보존한 채 일시 정지하고, 다음 메시지가 같은 VM 을 복원한다. 정지한 VM 은 나중에 회수될 수 있고(시점은 공개되지 않았다), 회수된 세션을 다시 열면 새 VM 에서 대화 기록만 복원된다. 이때 push 하지 않은 커밋과 커밋하지 않은 파일은 사라진다. 다른 세션은 처음부터 원격만 본다.

## Git

전역 §Git / 브랜치 의 "현재 브랜치에 direct commit · 브랜치를 만들지 않는다" 와 §문서 관리 의 "handoff 문서는 커밋하지 않는다" 를 이 절이 대체한다. PR 을 만들지 않는 것, 명시 경로만 스테이징, stash 금지, 커밋 단위가 작업 주제라는 것은 그대로다.

### 작업 브랜치

- 클라우드 세션은 시작할 때 임의 이름의 작업 브랜치(`claude/…`)를 만든다. 작업이 진행되는 동안 커밋·push 는 이 작업 브랜치에 한다. 세션을 시작할 때 고른 base 브랜치(main 등)에 직접 커밋하지 않는다.
- 작업 하나는 작업 브랜치 하나를 쓴다. 이어지는 세션(통합·구현·후속 피드백)은 자기가 새로 만든 브랜치가 아니라 그 작업의 브랜치로 옮겨 이어서 쌓는다. 사용자가 브랜치를 지정하지 않고 계획·인계 문서 경로만 주면 `git fetch` 뒤 `git log --all --format=%D -- <경로>` 로 그 문서가 있는 브랜치를 찾는다. 세션이 만든 빈 브랜치는 버린다(push 하지 않았으면 원격에 없다).
- 작업 브랜치에서는 후속 보완·결함 수정을 amend 대신 새 커밋으로 쌓는다 — main 에 들일 때 squash 가 한 커밋으로 묶는다. 작업 브랜치에 force push 하지 않는다.
- 커밋했으면 같은 턴 안에 작업 브랜치로 push 한다. 보고에 작업 브랜치 이름을 적는다 — 다음 세션이 이어받는 열쇠다.

### 계획·인계 문서

- 계획·인계 문서는 로컬과 같은 경로(레포의 gitignored plan/handoff 폴더)에 쓰고, 작업 브랜치에 `git add -f <경로>` 로 커밋·push 한다. gitignored 경로라 `-f` 없이는 스테이징되지 않는다.
- 대화로 방향을 조정하는 동안은 커밋하지 않는다. 세션의 산출물로 문서를 확정했을 때(계획 세션 완료·인계 지시·마무리 지시)나 사용자가 요청할 때 커밋·push 한다. 검증 통과는 기다리지 않는다.
- 세션 중 발견한 다른 주제의 인계 뼈대 문서(전역 §세션 체계)도 일단 작업 브랜치에 커밋해 두고, main 에 들일 때 아래 절차로 분리한다.

### main 에 들이기

사용자가 수정·피드백이 모두 끝났다고 알리면 그 작업을 main 에 들인다. 그 전에는 main 에 커밋하지 않는다.

1. 전역 §문서 관리 의 handoff 삭제 조건 ②③ 을 충족한 뒤, 작업 브랜치에서 그 작업의 계획·인계 문서를 `git rm` 해 커밋한다. 다른 주제의 인계 문서도 이 커밋에서 작업 브랜치에서 지운다(4번에서 옮긴다).
2. `git fetch` 뒤 main 을 `origin/main` 으로 맞추고 작업 브랜치를 merge 한다.
	- 기본은 `git merge --squash` 다. 커밋 메시지는 작업 주제 하나로 새로 쓴다. 계획 문서는 1번에서 지웠으므로 squash 결과에 남지 않는다.
	- 작업 브랜치가 `origin/main` 위의 작업 주제 커밋 하나뿐이고 계획·인계 문서 커밋이 없으면(단일 세션 trivial fix 등) `git merge --ff-only` 로 들인다.
	- 작업 중 발견한 기존 결함 수정처럼 다른 주제의 커밋이 섞여 있으면 그 커밋을 먼저 main 에 cherry-pick 해 별도 커밋으로 두고 나머지를 squash 한다(전역 §Git / 브랜치 의 커밋 단위).
3. main 을 push 한다. 그 사이 `origin/main` 이 움직여 거부되면 다시 fetch 해 2번을 반복한다 — main 에 force push 하지 않는다.
4. 다른 주제의 인계 문서가 있었으면 새 `origin/main` 에서 그 주제의 작업 브랜치를 만들어 문서를 옮겨 커밋·push 하고, 그 브랜치 이름을 보고한다.
5. merge 를 마친 작업 브랜치의 삭제는 사용자가 요청할 때만 한다.

### 정지 훅

- 클라우드 런처가 거는 정지 훅(`~/.claude/stop-hook-git-check.sh`, `launcher-settings.json` 의 `Stop`)은 커밋 안 된 변경·추적 안 된 파일·push 안 된 커밋이 있으면 응답을 끝낼 때 커밋·push 를 요구하는 경고를 한 번 돌려보낸다. 재귀 방지가 있어 경고 직후 다시 끝내면 통과한다.
- 이 경고는 커밋 시점을 정하지 않는다. 코드 변경은 전역 §Git / 브랜치 의 커밋 단위와 §시각 검증 의 "커밋은 검증 통과 뒤" 를 따르고, 커밋하지 않을 때는 이유를 한 줄 남기고 턴을 끝낸다. 조정 중인 계획·인계 문서가 경고 대상이 되어도 같다 — 확정 전에는 커밋하지 않는다.
- 경고에 따라 커밋·push 하는 곳은 작업 브랜치다. 경고를 이유로 main 에 들이지 않는다.

## 외부 CLI 위임

- codex·opencode·cmdc·agy·rtk 는 설치돼 있지 않다. 외부 CLI 모델이 지정돼도 쓸 수 없으므로 전역 §위임 매트릭스 의 대체 조항대로 Claude 서브에이전트로 대체하고 보고에 적는다. `~/.claude/models/` 의 CLI 런북은 이 환경에 해당하지 않는다.

## 시각 검증 구동

배정·위임 규칙은 전역 §시각 검증 이 갖고, 이 절은 이 환경의 구동 도구만 정한다.

- verifier 는 setup script 가 설치한 `agent-browser` 로 headless Chrome 을 구동한다. 브리프에 `~/.claude/models/AGENT_BROWSER.md` 경로와 verifier 별 `--session` 이름을 적는다 — 런북의 Git Bash·PowerShell·codex 샌드박스 조항은 해당하지 않는다. 메인 루프의 전 세션 정리 명령은 `agent-browser close --all` 이다.
- 브라우저가 닿는 도메인은 클라우드 환경의 네트워크 접근 수준이 정한다. 차단으로 보이는 실패는 우회하지 말고 대상 도메인과 오류를 그대로 보고한다.
