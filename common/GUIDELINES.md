# 공통 규율

여러 코딩 에이전트(Claude Code·Codex)가 함께 읽는 일반 원칙이다. 에이전트 고유 규칙은 각 에이전트의 전역 지침이, 레포 고유 규칙은 그 레포의 지침·canonical 문서가 갖는다. 절차·사례는 `→ 상세:` 가 가리키는 `~/.claude/memory/` 문서가 갖는다.

## 기본 규약

- 소스 파일은 UTF-8. Python 은 첫 줄 `# -*- coding: utf-8 -*-`, 콘솔 출력은 `sys.stdout.reconfigure(encoding='utf-8')` 로 고정한다(Windows cp949 대응). CSV 는 `utf-8-sig`, TXT 는 `utf-8`.
- **정확한 어휘**: 동작마다 의미를 정확히 짚는 동사를 쓴다(값을 넣다·기록하다·정의하다, 키를 추가하다, marker 로 감싸다). "박다" 계열(박기·박아·박는·박힌·박혀 등 활용형 포함)은 쓰지 않는다 — 별개 단어인 "박제" 는 예외.

## 결론 전 반증 조회

결론을 문장으로 쓰기 직전에 그것을 뒤집을 가장 값싼 조회를 떠올리고, 그것이 `ls`·`grep`·`--help`·산출물 열기·probe 한 번 수준이면 먼저 실행한다. 추론·정황·승계는 조회를 대신하지 못한다 — 틀린 결론은 그 위에 쌓인 추론·구현·검증 요구를 전부 낭비로 만든다.

- **승계한 주장은 인용이다.** 인계·계획 문서에서 가져온 부재·불가 주장은 조회로, 열린 항목은 지금 닫을 수 있는지로(§문서 관리), 검증 표본·판정 기준·게이트 기대치는 그 레포의 canonical·investigation 문서와 대조해 확인한다. 같은 항목을 이미 확정한 조사 문서가 있는지 먼저 grep 한다.
- **균일한 계측 결과는 도구 결함 신호다.** 전부 참·전부 0·전부 동일이면 다른 경로(직접 호출·다른 API·대조 표본)로 교차 확인한 뒤에만 근거로 쓴다.
- **관측을 대상에 귀속시키기 전에 산출물을 연다.** 관측을 특정 파일·코드 경로·식별자에 붙이려면 그 대상이 실제로 발행·실행되는 것인지 먼저 확인한다 — 같은 이름을 가진 대상이 둘 이상일 수 있다.
- **사용자가 확정해 말한 관측은 설명 대상이다.** 다시 보라고 요구하지 않는다. 기존 모델과 모순되면 노이즈가 아니라 반증으로 보고 모델을 재구성한다. 사용자에게 관측을 요청할 때는 경쟁 가설이 서로 다른 결과를 예측하는 표본만 고르고, 그 구분력을 요청 전에 조회로 확인한다.
- **플랫폼·런타임 동작을 근거로 불가능을 단정하지 않는다.** 관측 수단이 있으면 관측하고, 없으면 가정임을 밝혀 둔다.
→ 상세·사례: `~/.claude/memory/feedback_cheapest_falsifier_first.md`

## 부재·제한 판정

위 원칙의 부재 주장 특수형이다. "그런 도구·필드·경로는 없다", "이 식별자는 비공개 전용이다" 류는 실행한 조회 결과로만 말한다 — 틀린 단정은 실재하는 대상을 지우는 수정으로 이어진다.

- **도구**: harness·MCP 목록은 쓸 수 있는 것의 일부다. 전역 CLI(`codex`·`opencode`·`cmdc`·`agy`·`agent-browser`·`rtk`·`gh` 등)는 `which`·`--help` 로 확인한다.
- **식별자의 공개/비공개**: 커밋 트리를 grep 한다 — 이미 있으면 공개다.
- **확인 수단**: "X 가 없어 확인할 수 없다" 고 쓰기 전에 그 레포의 조사 문서(커밋 표면 밖 트리 포함)에서 같은 수단을 쓴 기록을 grep 한다. 기록이 있으면 수단은 있다.
- **사용자가 댄 이름은 고유명사로 보고 그 이름부터 조회한다.**

## 문서 관리

공통 원칙: 변경 history·경위는 문서 본문이 아니라 commit message 에 남긴다.

- **스펙/참조 문서**(CONTEXT·스펙·README 류)는 현재 상태만 단독으로 읽히게 쓴다. "이전: X / 현재: Y" 류 시계열 서술 금지. 설계 근거·대안 비교는 investigation 류 문서에 두고 본문에는 포인터 한 줄.
- **단일 출처**: 같은 사실은 권위 위치 한 곳에서만 기술하고 나머지는 참조한다.
- **파생 값 복사 금지**: 코드·출력에서 유도 가능한 수치(건수·커버리지)와 전수 목록은 본문에 옮기지 않고 권위 상수·코드 경로를 가리킨다. 측정 스냅샷은 investigation 류 문서에 측정 시점과 함께 둔다.
- **권위 문서 한국어 문장**: 커밋되는 권위 문서(스펙·CONTEXT·README·canonical 류) 본문을 쓸 때 `~/.claude/FLUENT_KOREAN.md` 를 읽고 적용한다. 대화 응답·plan/handoff·커밋 메시지·주석·브리프는 대상이 아니고, 종결어미는 레포 규범이 우선한다.
- **오류 정정은 결정 사항이 아니다.** 문서 기술이 틀린 줄 알면 묻지 않고 고친 뒤 무엇을 고쳤는지 보고한다. 사용자에게 묻는 것은 방향이 갈릴 때다.
- **계획 문서의 결정 확정**: 닫힌 결정은 채택안과 구현이 따를 제약만 남긴다. 기각 대안·저울질 경위는 본문에서 지우고, 보존 가치가 있으면 investigation 류 문서로 옮긴다. 함정 경고("X 로 하면 안 된다 — 이유")는 제약이므로 남긴다.
- **미확정 항목은 닫기를 시도한 뒤에 남긴다.** "열린 결정"·"후속 조사" 를 적기 전에 닫는 수단이 지금 실행 가능한지 판정하고, 가능하면 실행한다. 남겨도 되는 것은 사용자 결정 · 이 환경에서 실행 불가 · 실측 소요가 세션 예산 초과 · 다른 세션 소유 자원 필요(§동시 세션) 넷뿐이고, 사유는 추정이 아니라 시도 결과로 적는다. 하나를 닫아 문제 정의가 바뀌면 본문을 다시 쓴다. → 상세·사례: `~/.claude/memory/feedback_close_before_deferring.md`
- **"반영·갱신" 지시의 입력은 이미 끝낸 작업이다.** 새 실행을 얹지 않고 손에 있는 값으로 쓰며, 모자라면 모자란다고 알린다. 조사 자체가 산출물인 계획 세션은 해당하지 않는다.
- **handoff/인계 문서**는 세션 간 임시 문서다 — gitignored, 커밋하지 않는다. 본문은 다음 세션에 필요한 것(남은 작업·현재 상태·다음 단계)만 담고, 인계 지시가 있을 때만 읽는다. 삭제 조건은 셋이다: ① 변경이 커밋됐다(부분 검증 통과는 완료가 아니다) ② 그 문서에만 있는 미해결 항목·실측값·함정 경고를 영구 문서로 항목별 대조해 옮겼다(옮기며 맞는지 확인한다) ③ 삭제 뒤 그 문서를 가리키던 곳을 전수 grep 하고, 가리키던 문서는 포인터 한 줄이 아니라 전체를 현재 상태로 다시 읽어 고쳤다.

## 주석 원칙

주석의 독자는 유지보수자다. 코드가 하는 일의 재서술이 아니라 코드만 봐서는 보이지 않는 것을 적는다.

- **허용**: 코드로 표현되지 않는 제약(출력 바이트 동일성·순서 의존·외부 소비자 계약) · 도메인 결정의 근거 한 줄 + 권위 문서 포인터 · 함정 경고.
- **금지**:
	- 권위 문서에 이미 있는 규칙의 재서술 — 포인터로 대체한다.
	- 타 레포의 문서·코드 경로 지목 — 본 레포 권위 문서를 가리키고, 크로스레포 포인터는 그 권위 문서 한 곳만 갖는다. 타 레포와의 동치 제약 서술("생산측이 같은 규칙을 복제한다")은 허용.
	- 변경 경위("~에서 이동", "기존 호환") · 코드에서 유도 가능한 수치.
	- gitignored 임시 문서(plan/handoff) 참조. 주석이 가리킬 계약이 아직 plan 에만 있으면 그 시점에 권위 문서로 흡수하고 그쪽을 가리킨다.

## 코드 작성

### Dead Code 방지

레거시 경로·도달 불가 분기·실패를 삼키는 fallback 은 쓰지 않고, 쌓인 것은 지운다.

- **Fallback** 은 런타임에 두 경로가 모두 실제로 도달할 때만(네트워크 재시도·polyfill) 둔다. 오류를 삼키지 않는다.
- **Migration/Backfill/Backward-compat** 은 일회성 스크립트로 수동 실행하고, 명시 요청 없으면 git 에 넣지 않는다. 메인 코드에 듀얼 리드·포맷 감지·구 경로 fallback 을 남기지 않는다. → 상세: `~/.claude/memory/feedback_migration_policy.md`
- **추측 분기 금지**: 새 분기·enrichment 는 그 경로를 트리거하는 실제 데이터를 확인한 뒤에만 쓴다. 관측 몇 건의 상관으로 새 축을 세우지 않는다 — 관측이 계획 문서의 규칙과 어긋나 보이면 원본 코드를 정적으로 읽어 실제 규칙부터 확인한다. 규칙이 맞고 관측의 귀속이 틀린 경우가 흔하다.

### 화면 변경

- **착수 전에 디자인 문서를 읽는다.** 화면을 만들거나 고치는 작업(마크업·CSS·컴포넌트·레이아웃·반응형)은 구현·브리프 작성 전에 레포의 `docs/canonical/DESIGN.md` 를, 그것이 정하지 않은 축은 `~/dotfiles/common/FRONTEND_DESIGN.md` 를 읽고 적용한다. 렌더 결과로 판정하는 검증은 §테스트 설계 의 시각 검증 항목을 따른다.

### 선례·규칙 대조

- **"X 의 선례를 따르라" 는 선례의 전 표면이 대상이다.** 동작·마크업·스타일·문서를 모두 열어 대조하고, 일부 층(로직)만 보고 나머지(외형·표시 방식)를 추정으로 채우지 않는다.
- **레포 권위 규칙이 닿는 변경은 규칙 절을 먼저 대조한다.** 구현·브리프 작성 전에 그 규칙 절(UI 변경이면 §화면 변경 의 디자인 문서)을 읽고, 위임 결과 검토(spec 적합성)의 기준에도 같은 규칙을 넣는다. 브리프에 적은 값이 규칙을 어기면 위임자는 그대로 구현하므로 브리프가 결함의 출처가 된다.

### 버그 수정

- 원인 확정 전 수정 금지 · 공식 문서 우선 · 전제 재검증 · 배포/빌드는 원인 확정 뒤. → 상세·사례: `~/.claude/memory/feedback_dont_fix_what_you_didnt_break.md`
- **기존 피해를 전수 정리한다.** 그 버그가 이미 만든 잘못된 데이터(중복 파일·오기록·잘못된 상태)를 전수 검색해 한 번에 정리한다.
- **인과는 메커니즘과 site 를 함께 확정한다.** 한 요소를 여러 규칙·경로가 제어하면 전 경로를 열거하고 결함이 어느 경로에서 트리거되는지 특정한다. "X 경로에서만" 류 스코프 관측은 X 고유 메커니즘을 가리킨다.
- **간헐·전이 결함은 발현 조건을 강제해 검증한다.** 캐시·빠른 회선·즉시 완료 같은 편한 조건의 통과는 거짓 통과다.
- **같은 증상의 재수정은 이전 모델이 불완전하다는 신호다.** 완화책을 덧대지 말고 이전 모델이 설명하지 못한 관측을 찾아 전 경로를 재구성하고, 가능하면 경로를 하나로 통일한다.

### 테스트 설계

테스트는 구현이 아니라 외부 계약·실제 call seam·관측 가능한 결과를 검증하고, 실행 시간·유지비·실패 해석 비용에 상응하는 고유 검출력을 가져야 한다. 개수는 품질 지표가 아니다.

- **tautological test 금지**: 구현의 상수·분기를 복사해 비교하거나, mock 이 반환하게 한 값을 그대로 assert 하거나, private helper 를 재서술하지 않는다.
- **테스트가 해를 정의하지 않는다**: 테스트 입력에만 맞는 해로 통과시키지 않는다. 테스트가 틀렸거나 과제가 불가능하면 보고한다.
- **중복 금지**: 기존 테스트가 같은 계약을 이미 검출하면 이름·입력만 바꾼 테스트, 라이브러리 동작 검증, coverage 용 테스트를 추가하지 않는다.
- **회귀 검출력**: 버그 수정 테스트는 수정 전 실패·수정 후 통과를 확인한다. 수정 전 실행이 불가능하면 시도 결과와 검증 제한을 보고한다.
- **최소 seam**: 원인에 가장 가까운 공개/통합 seam 에 둔다. private helper 테스트는 독립 계약이 있을 때만.
- **suite 경계**: benchmark·전수 변환·브라우저 검증은 유닛 suite 에 넣지 않는다. 편집 중에는 변경 seam 의 targeted test 만 돌리고, 전체 suite·typecheck·빌드는 최종 상태에서 한 번 돌린다. 코드·입력이 그대로면 같은 검증을 반복하지 않는다.
- **시각 검증**: 브라우저 렌더 상태로 판정하는 검증의 브리프·판정 규약은 `~/dotfiles/common/VISUAL_VERIFICATION.md` 가 갖는다.
- correctness·security·data-integrity 회귀 테스트를 줄이라는 뜻이 아니다 — 기준은 개수가 아니라 고유 검출력과 비용이다.

### 성능과 자원 효율

성능은 설계·구현·검토의 수용 기준이다 — 특히 전수·batch·변환·인덱싱 작업.

- **규모를 먼저 적는다.** 구현 전에 입력 개수 × 중첩 반복으로 내부 실행 횟수와 peak memory 상한을 적고, 그 규모에 맞는 처리 형태(배열 연산·스트리밍·캐시)를 고른다. 표본 하나의 성공은 전수 실행의 적합성이 아니다. → 상세: `~/.claude/memory/feedback_array_first_hot_paths.md`
- **중복 계산 금지**: 같은 source 에서 여러 출력을 만들 때 parse·decode·변환은 한 번만 실행하고, 그 중간 결과에서 나머지를 파생한다.
- **메모리 상한을 소유한다**: 전체 입력의 디코드 결과나 대형 payload 를 편의로 전역 컬렉션에 쌓아 두지 않는다. 가벼운 메타데이터 인덱스·지연 materialization·스트리밍·청크로 peak memory 가 전체 항목 수에 비례하지 않게 한다.
- **병렬화는 설계 단계에서 검토한다.** 독립 단위가 많고 단위당 작업이 큰 전수·batch 작업은 병렬을 기본으로 설계한다. 방식은 병목으로 고른다 — CPU 가 병목인 순수 Python 코드는 GIL 때문에 스레드로 빨라지지 않으므로 프로세스로 나누고, I/O 대기가 병목이면 스레드·async 를 쓴다. 단위가 작아 직렬화·기동 비용이 이득을 넘거나, 병목이 먼저 줄일 수 있는 행당 CPU(메모이즈·인덱스·중복 호출 제거 대상)이면 직렬로 둔다. 채택과 기각은 같은 조건의 worker 1 대 N wall 비교로 판정하고, 동시 수는 코어·메모리·외부 rate limit 으로 제한한다.
- **병렬 정합 조건**: worker 가 상태·임시 출력을 독점하고 순서·최종 publish 는 parent 가 정한다. 결과는 완료 순서와 무관하게 같아야 하고, 실패하면 남은 작업을 취소하고 부분 결과를 승격하지 않는다.
- **구조 우선**: micro-optimization 전에 중복 패스·eager loading·반복 직렬화를 없앤다. 프로파일러는 후보 발굴용이고 효과 판정은 같은 조건의 wall 비교다. 성능 tradeoff("N배 부하")는 실측 뒤에만 주장하고, 성능 개선을 이유로 계약·검증을 완화하지 않는다.
- **측정은 의무다.** 새 전수 실행기·계측 도구는 전량 1회 실측(wall·peak memory·처리량)이 완료 조건이고, 값은 조건·시점과 함께 investigation 류 문서에 남긴다. 병목은 CPU 사용률·I/O 대기·paging 을 구분해 판단한다. 느린 것을 보고도 재지 않고 넘기지 않는다.
- **동치는 원소 단위로**: 재작성·벡터화의 합격 기준은 이전 구현과의 원소 단위 일치이고, 배치 = 개별 평가 동치를 테스트로 고정한다.
- **장시간 실행은 결함 후보다.** 상한은 같은 조건의 기록된 정상 wall 의 1.5배, 기록이 없으면 10분이다. 넘으면 결함으로 보고 중단한다 — "전수라서 원래 오래 걸린다" 는 근거가 아니다. 착수 전에 소요를 예측하고(기록 → 없으면 단위 하나를 재서 외삽), 크게 벗어나면 프로파일한다. 전수 게이트는 변경이 건드린 대상으로 좁혀 돌린다 — 입력·산출물 바이트가 안 바뀐 대상의 판정은 안 바뀐다. 기록이 없던 전수 명령을 완주했으면 wall 을 조건과 함께 기록한다. 성능이 세션 목표면 개선하고, 범위 밖이면 백그라운드로 돌리고 다른 일을 한다(포그라운드 폴링 없음). 기준선 캡처 명령 자체가 개선 대상이면 개선을 먼저 한다. → 상세: `~/.claude/memory/feedback_long_run_is_a_defect_signal.md`

## 탐색과 읽기

- 순서: 메모리 → CONTEXT 문서 → 직접 조회(파일 읽기·검색) → (마지막) 탐색 에이전트. → 상세: `~/.claude/memory/feedback_memory_before_explore.md`
- 광역 검색(재귀·대규모 Grep/Glob)은 디스크 I/O 가 크므로 기본적으로 피하고 직접 경로 조회로 대신한다. 완전성이 목적인 작업(버그 영향 전수 조사·심볼 전역 사용처·일괄 정정 대상 수집)에서는 빠짐없이 훑는 쪽을 우선한다.
- 도구 결과는 전부 컨텍스트에 남는다. Bash 호출 하나의 출력은 약 150줄이 상한이고, 파일 여러 개를 이어 출력하지 않는다. 큰 파일은 심볼 목록을 먼저 뽑고 필요한 범위만 읽는다.
- "Output too large … saved to" 가 뜨면 spill 파일을 통째로 되읽지 않고 범위를 좁혀 다시 실행한다. 재실행할 수 없는 출력(장시간 실행 결과)만 예외이고, 그때도 grep·범위 읽기로 필요한 부분만 본다.

## 동시 세션

같은 기기·같은 워킹 트리에서 여러 세션이 병행한다. 파일이 겹치지 않아도 실행 자원(dev 서버와 포트·브라우저·GPU·캡처와 측정 산출물·워킹 트리의 rev)은 겹친다.

- 다른 세션이 진행 중인 활동의 자원은 그 세션 소유다 — 잡지도, 상태를 바꾸지도, 되살리지도 않는다. 사용자 통지가 없어도 분리 HEAD·내가 옮기지 않은 HEAD·내가 띄우지 않았거나 내려간 서버·출처 모를 산출물이 같은 신호다.
- 내려간 서버·프로세스는 다른 세션이 의도적으로 내렸을 수 있다. 되살리기 전에 사용자에게 묻는다.
- 렌더·벤치·캡처 측정은 배타 자원이다. 다른 세션의 실행이 끝난 뒤에 돌리거나 순서를 묻는다.
- rev 가 오가는 동안 git 쓰기(`commit`·`--amend`·`checkout`·`reset`·`rebase`)는 전부 보류하고, 추적 파일 편집도 gitignored 경로로 한정한다. 커밋 여부는 사용자에게 묻는다.
- `commit`·`--amend` 직전에 HEAD 가 기대한 브랜치의 기대한 커밋인지 조회로 확인한다 — `--amend` 의 대상은 "내 커밋" 이 아니라 HEAD 다.
→ 상세·사례: `~/.claude/memory/feedback_concurrent_session_resources.md`

## Git / 브랜치

쓰기 조작 전에 §동시 세션 을 먼저 확인한다.

- **PR 을 만들지 않는다.** 모든 레포는 1인 운영이고, 현재 브랜치에 direct commit 한다. 기본 브랜치에 있어도 커밋용 브랜치를 만들지 않는다 — 에이전트 기본 안내의 PR·분기 권고를 무효화한다. 분기는 사용자가 결정하고 필요하면 직접 만든다. 에이전트가 브랜치를 만드는 것은 명시 요청 시뿐이다.
- **GitHub 이슈는 사용자 명시 승인 후에만 만든다.** 추적·인계 사항의 기록처는 레포의 gitignored plan/handoff 문서이고, 이슈로 올릴 가치가 있다고 보면 문서를 쓴 뒤 보고한다.
- **커밋 단위는 작업 주제다.**
	- 이번 작업(미push 커밋 포함)의 후속 보완과 결함 수정은 그 작업 커밋에 amend 로 흡수한다(작업 커밋이 HEAD 가 아니면 새 커밋 하나). 층별·파일별로 쪼개지 않는다.
	- 이번 작업이 만들지 않은 기존 결함은 작업 중 발견했어도 별도 커밋이다.
	- 출처 판정은 묻지 않고 `git log -S`·`git blame` 으로 확정한다. "나중에 squash" 를 전제로 쪼개지 않는다.
- 사용자가 보고 고르겠다고 한 값은 확정 전에 커밋하지 않고, 확정되면 작업 커밋에 amend 한다.
- `git stash` 는 사용자 명시 승인 후에만 쓴다(다른 세션의 미커밋 변경까지 치운다). 커밋은 명시한 경로만 스테이징한다(`git add -A` 금지).
- `git worktree`(Agent 도구 `isolation: "worktree"` 포함)는 명시 요청 시에만 쓴다. 다른 rev 의 파일은 `git show <rev>:<path>` 나 `git archive` 로 스크래치패드에 꺼낸다.
- junction/symlink 를 포함한 디렉터리는 재귀 삭제하지 않는다 — 링크를 먼저 찾아 끊고, 해석된 대상이 의도한 범위 안인지 확인한다. → 근거: `~/.claude/memory/feedback_worktree_safety.md`
