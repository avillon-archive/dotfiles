# 프론트엔드 디자인 원칙

화면을 만들거나 고치는 레포에서 읽는다. 레포의 `docs/canonical/DESIGN.md` 가 이 문서보다 우선하고, 이 문서는 DESIGN.md 가 정하지 않은 축의 기본값과 DESIGN.md 를 쓰는 규범을 정한다. 브라우저로 판정하는 검증의 규약은 `VISUAL_VERIFICATION.md` 가 갖는다.

## 착수 절차

- **DESIGN.md 가 있으면 그것을 따른다.** 정하지 않은 축만 이 문서로 채우고, 새 토큰·패턴이 필요하면 같은 변경에서 DESIGN.md 에 등록한다.
- **DESIGN.md 가 없는 레포에서 화면을 새로 만들면 코드보다 DESIGN.md 를 먼저 쓴다.** 대상(무엇을 보여 주는 도구이고 누가 쓰는가), 이름 붙인 4~6개의 색, 서체와 역할, 레이아웃 개념, 이 화면만의 원칙을 정하고, 사용자에게 보인 뒤 구현한다.
- **도구형 UI 는 장식보다 정보 밀도와 가독성이 우선이다.** 개성은 다루는 대상의 세계(원작의 색·형태·어휘, 데이터의 도메인)에서 끌어오고, 과감함은 한 곳에만 쓴다.

## 토큰과 스케일

- 색·크기·간격·반지름·그림자·모션 시간의 단일 출처는 CSS custom property(`:root`)다. 그 밖에 리터럴로 쓸 수 있는 값(`0`, 1px 경계, `100%` 등)은 레포의 DESIGN.md 가 열거한다.
- 스케일은 닫혀 있다 — 단계에서 고르고 중간값을 만들지 않는다.
- 스케일 밖 값이 필요하면 이 순서로 판단한다.
	1. 기존 단계와 ±10% 이내면 기존 토큰을 쓴다 — 눈으로 구분되지 않는 두 토큰은 스케일을 무너뜨린다.
	2. 단일 사용처의 특수 값은 토큰으로 만들지 않고 리터럴과 근거 주석으로 쓴다.
	3. 같은 값이 두 곳 이상에서 반복되거나 기존 스케일과 평행한 새 계열을 이루면 토큰을 신설하고, 같은 변경에서 DESIGN.md 에 등록한다.
- 원본을 재현한 실측값, vendor 기본값의 복제, 레이아웃 골격의 구조 상수는 스케일 대상이 아니다 — 출처를 주석으로 적는다.

## Colors

- 역할 토큰으로 칠한다. 파생의 기준이 되는 색은 직접 칠하지 않는다. 회색 단계는 한 계열에서 파생해 색조가 섞이지 않게 한다.
- 강조색은 쓰는 자리를 DESIGN.md 에 열거하고 그 밖에 쓰지 않는다.
- 도메인 의미를 가진 색(분류·속성 색)은 범용 강조에 쓰지 않는다 — 보는 사람이 그 분류로 읽는다.
- 정보를 전달하는 글자는 WCAG AA 대비(본문 4.5:1)를 지킨다. placeholder 도 정보이고, 면제는 비활성 컨트롤뿐이다.
- 어두운(inverted) 표면은 쓰는 자리를 DESIGN.md 에 열거한다.
- 팔레트는 대상에서 끌어온다. 크림 배경과 세리프·테라코타 액센트, 근흑 배경과 형광 액센트처럼 대상과 무관하게 반복되는 정형 팔레트를 쓰지 않는다.
- 그라데이션은 장식으로 쓰지 않는다.

## Typography

- UI 서체는 한 계열, 필요하면 뚜렷이 다른 두 계열까지 쓴다(원작 재현 표면의 서체는 콘텐츠라 별개다). 서체 스택은 역할별 토큰 하나로 두고 표면에 직접 나열하지 않는다.
- 굵기는 본문과 강조 두 단계다. 크기는 닫힌 rem 스케일에서 고르고, 자기 font-size 에 비례해야 하는 기하(아이콘 높이·글자에 붙은 반지름)는 em 리터럴로 쓴다.
- 라벨·번호·구분선 같은 구조 장치는 정보를 담을 때만 쓴다 — 제목마다 얹는 대문자 eyebrow 라벨, 순서가 아닌 내용의 01/02/03 번호, 장식용 메타 정보 줄을 쓰지 않는다. 제목에서 한 단어만 기울임·색으로 강조하지 않는다.
- 긴 산문을 담는 컨테이너에는 폭 상한을 둔다 — 넓은 화면에서 한 줄이 끝없이 늘어나지 않게 한다.
- 화면 문구:
	- 사용자의 어휘로 이름 짓고 구현 어휘를 드러내지 않는다.
	- 동작의 이름은 흐름 내내 같다(버튼 "저장" → 결과 "저장했다").
	- 오류 문구는 무엇이 일어났고 어떻게 고치는지를 말하고, 막연하게 쓰지 않는다.
	- 빈 상태는 다음 행동을 안내하는 한 줄로 쓴다. 큰 아이콘과 제목을 놓는 랜딩 페이지 문법을 쓰지 않는다.

## Layout

- **간격은 요소 사이의 의미 거리로 고른다.** 독립 블록 사이 · 한 컴포넌트의 내부 부품 사이 · 한 덩어리로 읽혀야 하는 밀착 부품 사이에 각각 한 단계를 대응시키고, 같은 관계에는 같은 단계를 쓴다. 모든 간격을 한 단계로 통일하면 의미 거리가 지워진다.
- 간격은 부모의 `gap` 이 소유한다 — 자식 margin 으로 간격을 만들지 않는다.
- **넘침은 항목 단위로 줄바꿈하지 않는다.** 그룹 단위로 줄을 바꾸거나, 행 단위 가로 스크롤(스크롤바 숨김 + 끝단 페이드 큐)로 받는다. 줄바꿈하는 행의 그룹 사이에는 구분선을 두지 않는다 — 줄이 바뀌면 줄 머리에 구분선이 남는다.
- 공간이 모자랄 때 무엇부터 물러나는지 순서를 DESIGN.md 에 적는다.
- 모드 전환이나 값 변경으로 상자 크기가 흔들리지 않게 자리를 예약한다.

## Elevation & Depth

- 영역은 경계선과 표면색 차이로 먼저 나누고, 그림자는 떠 있는 표면에만 쓴다. 모든 내용을 같은 모서리·같은 회색 그림자의 카드로 자르지 않는다.
- z-index 는 DESIGN.md 의 대장 표에 층 이름과 순서 근거를 등록한 값만 쓴다. 컴포넌트 내부의 지역 stacking 은 대장 대상이 아니다.
- 상호작용을 막는 오버레이(dimmer)의 값은 하나로 통일한다.

## Shapes

- 반지름은 위계에 따라 단계를 나눈다 — 모든 요소에 같은 반지름을 쓰지 않는다.
- 터치 타깃은 44×44px 이상이다. 같은 값의 레이아웃 토큰이 있어도 터치 최소는 별개 의미이므로, 레이아웃 토큰이 바뀌어도 이 하한은 내려가지 않는다.
- 한 줄에 놓이는 컨트롤의 높이는 토큰 하나로 맞춘다.

## Components

- **아이콘**: UI 아이콘은 아이콘 폰트 글리프로 쓴다. 주 계열 하나를 쓰고 그 안에 없는 글리프만 보조 계열 하나에서 가져오며, 글리프 목록의 권위는 한 곳에 둔다.
- **클릭할 수 있는 아이콘에는 동작이 있다.** 자체 기능이 없는 라벨 아이콘은 연관 컨트롤의 활성화(select 열기, input focus)로 배선한다. 버튼 크롬(테두리·배경)의 유무는 취향이 아니라 영역 분리를 무엇이 담당하는지로 정한다.
- **라벨**: 축의 이름은 라벨과 옵션 텍스트 중 한 곳에만 둔다. 의미가 아이콘 하나와 1:1 이면 아이콘, 아니면 텍스트로 쓴다. 보이는 라벨이 없으면 `aria-label` 이 이름을 갖는다.
- **토글 글리프**:
	- 행동으로 읽히는 동사형 쌍(`play`/`pause`, `expand`/`compress`, `eye`/`eye slash`)은 누르면 바뀔 상태를 표시한다. 현재 상태가 화면에서 자명할 때만 성립한다.
	- 사물의 상태로 읽히는 명사형 쌍(열린/닫힌 봉투, 켜진/꺼진 전구), 대등한 모드 선택, 3단 이상 순환은 현재 상태를 표시한다.
	- `aria-pressed`(2단 한정)·`aria-label` 은 늘 현재 상태를 서술하고, 글리프는 `aria-hidden` 이다.
- **hover** 는 장식에만 쓰고 `@media (hover: hover) and (pointer: fine)` 안에서만 적용한다. hover 로만 닿는 기능을 두지 않는다.
- **포커스**: 포커스 표시는 `:focus-visible` 로 걸어 키보드 조작에서만 보이게 한다 — 마우스·터치 조작에는 나타나지 않는다. 앱은 전역 베이스라인 하나(특이도 0)를 두고 컴포넌트마다 링을 새로 그리지 않으며, 경계와 겹치는 곳만 offset 을 조정한다. 호스트에 임베드되는 라이브러리는 링을 그리지 않고 브라우저 기본 표시와 호스트 규약에 맡긴다. 표시를 다른 형태(테두리 색 전환 등)로 바꾸는 것은 되지만, 대체 없이 지우지는 않는다.
- **조건부 표시**는 `hidden` 속성 하나로 하고, `display` 를 지정한 author 규칙이 `[hidden]` 을 덮지 않게 보장한다.
- **작업 상태**: 진행과 오류는 한 곳에만 표시하고, 같은 오류를 다른 영역에서 다시 보고하지 않는다.

## Responsive Behavior

- 반응형은 축소가 아니라 입력 방식·화면 자세에 맞춘 재배치다. 계획 단계에서 구간마다 레이아웃을 정하고, 데스크톱을 완성한 뒤 모바일을 덧대지 않는다.
- 구간은 기기나 입력 방식이 아니라 사용할 수 있는 폭·높이로 판정한다 — 짧은 높이도 좁은 폭과 같이 공간 부족으로 다룬다.
- 권위 media query 문자열은 하나이고 CSS 와 JS 가 같은 문자열을 쓴다. JS 는 `matchMedia` 로 판정하고 산술로 재구현하지 않는다.
- 검증 뷰포트의 선정은 `VISUAL_VERIFICATION.md` §뷰포트 를 따른다.

## Motion

- **모션은 근거가 있을 때만 쓴다.** 근거는 셋이다.
	1. 모션이 콘텐츠 자체다(원작 연출의 재현, 재생형 미디어). 재현 모션은 원본에 없는 움직임을 더하지 않는다.
	2. 사용자 조작의 결과로 무엇이 바뀌었는지 보여 준다(패널 열림, 선택 확인).
	3. 놓치면 안 되는 변화 하나에 주의를 끈다.
- 근거 없이 생동감을 위해 넣는 모션(섹션마다 붙는 등장 효과, 모든 카드의 hover 전환, 장식 반복 애니메이션)은 쓰지 않는다. 근거가 있어도 모션은 필수가 아니다 — 즉시 전환을 택하는 레포가 있다.
- 지속 시간과 easing 은 토큰으로 둔다. 등장·퇴장에는 감속 곡선을 쓰고 UI 에 `ease-in` 을 쓰지 않는다.
- `prefers-reduced-motion` 에서는 근거 2·3 의 모션을 끄고 정보만 남긴다 — 바뀌었다는 사실은 즉시 전환으로 전달한다. 근거 1 의 처리는 레포가 정하고, 그 결정을 DESIGN.md 의 Motion 절에 적는다.

## Loading & Transitions

- 화면을 전환할 때 공유 골격은 유지하고 필요한 부분만 교체한다.
- 늦게 도착하는 콘텐츠(이미지·폰트·비동기 데이터)가 이미 보이는 레이아웃을 밀어내지 않게 한다 — 자리를 확보하거나 준비가 끝날 때까지 숨긴다.
- 로더는 콘텐츠를 완성된 상태로 보일 수 있을 때까지 유지하고, 로더 자신의 리소스가 준비되기 전에는 로더를 노출하지 않는다.
- 이 항목들의 위반은 빠른 회선·따뜻한 캐시에서 드러나지 않는다 — throttle·콜드 로드로 발현 조건을 강제해 검증한다.

## Do's and Don'ts

본문 규칙 가운데 실제로 자주 어기는 것이다. 근거와 범위는 각 절이 갖는다.

- 새 값은 토큰에서 고른다 — 스케일 밖 리터럴을 근거 없이 쓰거나 여러 곳에 복제하지 않는다.
- 간격을 한 단계로 통일하지 않는다 — 관계마다 단계가 다르다.
- 항목 단위로 줄바꿈하지 않는다.
- 데스크톱을 완성한 뒤 모바일을 덧대지 않는다.
- hover 로만 닿는 기능을 두지 않는다.
- 포커스 링을 새로 그리지 않는다 — 앱은 전역 `:focus-visible` 베이스라인 하나를 쓰고, 라이브러리는 브라우저 기본 표시와 호스트에 맡긴다.

## DESIGN.md 작성 규범

- **위치**: `docs/canonical/DESIGN.md`.
- **골격**: Overview · Colors · Typography · Layout · Elevation & Depth · Shapes · Components · Responsive Behavior · Motion · Loading & Transitions · Do's and Don'ts. 앞 여덟 절의 이름과 순서는 google-labs-code/design.md 형식과 같다. 제목은 영어로, 본문은 레포의 언어로 쓴다. 해당 없는 절은 생략하되 있는 절은 이 순서를 지키고, 레포 고유 절은 Components 와 Do's and Don'ts 사이에 둔다.
- **YAML front matter 를 두지 않는다.** 값의 권위는 CSS 이고, front matter 를 쓸모 있게 하려면 검사·생성 도구 의존성이 따른다. 도구 없이 손으로 적은 front matter 는 CSS 값의 복사본일 뿐이다.
- **본문은 토큰의 이름·역할·쓰임 규칙과 근거를 적고 값을 옮기지 않는다.** 값 자체가 계약인 것(분기점 query 문자열, 터치 최소 크기처럼 바뀌면 규칙이 달라지는 값)만 예외다.
- **넣지 않는 것**: 구현 함정과 특이도 우회(코딩 규칙 문서) · 기능별 동작과 상태 계약(context 문서) · 레퍼런스 선정 근거와 추출값(investigation 문서) · 파일 목록처럼 저장소에서 유도되는 것.
- **Overview** 는 화면이 무엇이고 누구를 위한 것인지, 따르는 레퍼런스, 테마 범위를 적는다.
- **Do's and Don'ts** 는 본문 규칙 가운데 실제로 자주 어기는 것만 짧은 문장으로 모은다. 본문에 없는 새 규칙을 여기서 만들지 않는다.
