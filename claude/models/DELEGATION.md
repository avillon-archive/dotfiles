# OpenCode·CommandCode 위임 공통 런북

OpenCode·CommandCode 로 호출하는 모델에만 적용한다. Codex(Sol/Luna)는 대상이 아니며 `CODEX.md` 만 따른다. 사용 조건·역할·effort 원칙은 `~/.claude/rules/local.md` §외부 CLI 위임 이 정하고, CLI 별 호출·모델 표·권한·진행 확인은 각 런북이 갖는다. 관측 경위는 `investigation/CLI_DELEGATION_OBSERVATIONS.md`.

| CLI | 런북 | 모델 |
|---|---|---|
| `opencode` | `OPENCODE.md` | DeepSeek Flash · Muse Spark 1.3 (· Free) |
| `cmdc` (CommandCode) | `COMMANDCODE.md` | DeepSeek Flash |

- **브리프 파일은 임시 문서다.** 작업 커밋 후 삭제하고, 커밋되는 파일에서 그 경로를 참조하지 말라고 브리프에도 적는다.

## 브리프 전달

브리프는 레포 안 gitignored 경로(`docs/plan/briefs/<작업명>.md` 등)에 쓰고, 프롬프트에는 그 경로를 지목하는 한 줄만 넘긴다.

편집 명령과 첫 편집 대상 파일 이름은 **호출 프롬프트 자체에** 적는다. 브리프 안에만 적으면 첫 편집에 닿지 못하는 런이 나온다.

```
docs/plan/briefs/<작업명>.md 를 읽고 그대로 수행할 것. 레포 루트 CLAUDE.md 의 규칙도 함께 지킬 것. 브리프를 읽은 직후 <가장 먼저 만들/고칠 파일> 편집부터 시작하고, 편집 없이 종료하지 말 것.
```

- **브리프는 자립적으로 쓴다.** 계획 문서 같은 대형 문서를 지목하지 않고 필요한 발췌·시그니처·수용 기준을 옮겨 적는다. 읽기 대상은 수정 대상 소스와 그 테스트로 한정한다 — 컨텍스트가 커질수록 첫 편집까지의 스텝과 재개 비용이 는다.
- **런 하나에 단위 하나.** 한 런이 끝까지 해내는 편집량은 파일 두어 개 규모다. 전역 §위임 단위 보다 잘게 나누고 단위마다 새 런(또는 같은 세션의 다음 지시)으로 넘긴다.

## 브리프 작성

- 대상 파일 경로·수용 기준·완료 후 실행할 검증 명령을 적고 **출력 원문 첨부**를 요구한다.
- 산출물을 명시한다 — "파일 편집이 산출물이며 조사·probe 로 끝내지 말 것", 종료 전 `git diff --stat` 확인 → 검증 명령 실행.
- 커밋까지 맡길 때만 커밋을 지시하고, 아니면 "커밋하지 말 것" 을 적는다.
- 읽을 문서는 §필수 조항 의 `## 읽을 문서` 블록으로 지목한다. 산문으로 흘려 쓴 "CLAUDE.md 도 지킬 것" 은 읽히지 않는다.
- **외부 형식의 실물 입력을 읽거나 쓰는 코드(파서·변환기)는 실물 입력 스모크가 합격선이다.** 영향 대상 1건의 실제 변환이 성공하고 산출물에 기대값이 실리는 것을 확인하게 하고, 그 명령·기대값을 적고 출력 원문을 요구한다. fixture 는 구현의 가정이 아니라 실데이터에서 관측한 모양으로 만들게 한다. 명령은 그 레포의 검증 문서(`docs/canonical/TESTING.md` 류)가 갖는다.
- **큰 산출물은 쪼개 쓰게 한다.** 브리프와 호출 프롬프트 양쪽에 "먼저 제목 줄만으로 파일을 만들고, 입력 하나를 읽을 때마다 그 섹션을 append 하라" 를 적는다. 첫 쓰기가 크면 그 턴에서 스트림이 끊긴다(→ §편집 없이 끝나는 런).
- **작업 트리를 일시적으로 망가뜨리는 확인을 시키지 않는다.** 런은 임의 지점에서 끝날 수 있어 되돌린 상태가 트리에 남고, 같은 트리의 다른 세션도 그 상태를 본다. 새 테스트가 계약을 잡는지(소스를 되돌려 red 확인)는 메인 루프가 본다.

### 필수 조항 (매 브리프에 이 형태 그대로 — 본문에 문장으로 흘려 쓰면 무시된다)

```markdown
## 읽을 문서 (편집 전에 읽는다)

1. 레포 루트 `CLAUDE.md` 전체.
2. 전역 지침 `~/.claude/CLAUDE.md` — 이 CLI 가 전역 지침을 자동 로드하지 않을 때만(opencode 는 `opencode.jsonc` `instructions` 로 로드하므로 생략). `→ 상세·사례:` 포인터는 따라가지 않는다.
3. 이 작업이 닿는 권위 문서의 절: <레포 `docs/canonical/**` 의 § 목록 — 테스트를 더하면 테스트 설계 규칙 절, 검증 명령은 최소 실행 절>.

## 임시 파일

임시 스크립트·중간 산출물은 워크스페이스(레포) 안에만 만든다(CLI 별 추가 허용 경로는 해당 런북 §권한). 그 밖의 경로 쓰기는 권한 거부로 실패한다. 확인이 끝나면 삭제하고, 삭제했는지 종료 전에 확인할 것.

## 금지 사항 (엄수)

- git commit·스테이징 금지. **git stash 절대 금지**(같은 워킹 트리의 다른 세션 변경까지 치운다). `git add -A` 금지. 브랜치 생성·전환 금지.
- 수정 범위는 <경로 목록> 뿐이다. 그 밖의 파일은 읽기만 할 것.
- 테스트를 약화시켜(단언 삭제·skip·조건 완화) 통과시키지 말 것. 실패가 소스 결함을 가리키면 보고할 것.
- 소스를 되돌렸다가 복구하는 확인 금지(`git checkout`·역편집 포함). 확인이 필요하면 그 필요를 보고에 적을 것.
```

## 편집 없이 끝나는 런 (가장 흔한 실패)

런이 정상 종료했는데 파일이 하나도 바뀌지 않는 경우다. 출력 로그에 읽기 도구만 있고 쓰기 호출이 없으면 이것이다. 모델이 그 턴의 출력을 전부 추론에 쓰고 도구 호출도 텍스트도 내지 않은 채 스트림이 끝나며, 끊기는 지점은 **처음으로 큰 산출물을 써야 하는 턴**이다(CLI 별 확증 절차는 각 런북).

- **판정**은 보고 문구가 아니라 대상 파일의 mtime·`git status` 로 한다. 요구한 검증 출력 원문이 없으면 미실행으로 본다. 보고서류는 `wc -l` 이 0~1 이면 이 실패다.
- **대응은 재개다.** 세션을 이어가면 읽어 둔 컨텍스트 위에서 편집이 나간다. 재개 지시는 다음 행동 하나를 구체적으로 정하고("지금 `<경로>` 를 만들어라"), 남은 항목을 번호로 열거하며, 브리프를 다시 읽으라고 하지 않는다. 산출물이 크면 재개 지시에도 "블록 하나씩 append" 를 적는다.
- 같은 세션이 즉시 빈 응답을 내면 그 세션은 죽은 것이다 — 브리프를 더 잘게 쪼개 새 세션으로 시작한다.
- 재개·재시도를 두세 번 해도 편집이 0 이면 위임을 접고 메인 루프가 직접 구현한다.

## 검증 결과 신뢰 — 재실행이 아니라 증거로

브리프가 증거를 요구하고, 메인 루프는 증거의 유무·정합과 diff 의 스펙 적합성을 본다.

- 브리프가 요구할 것: 검증 명령의 출력 원문(테스트 요약 라인·실측 숫자) · 실행 못 한 검증의 사유.
- 메인 루프가 재실행하는 경우는 셋뿐이다: 증거가 없거나 잘렸을 때 · 숫자가 어긋날 때 · diff 검토에서 보고와 다른 동작이 의심될 때. 이때도 의심 지점만 좁혀 확인한다.
